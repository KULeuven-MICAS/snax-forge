# dot_1_shared at trace levels task and stall

A recorded SNAX-GVSoC run of two groups sharing one streamer's movers (D169), so CI converts a shared design without GVSoC (`tests/run/test_shared.py`): dot_1_shared, the accelerator `dot` of groups `vmul` and `vsum` on one streamer set `dot` (`share_ports`), a task each; `dot_reader0` carries `vmul_a` and `vsum_a`, `dot_reader1` `vmul_b` only (idle in vsum's task), `dot_writer0` `vmul_out` (4 channels) and `vsum_out` (its first channel, ENABLED_CHANNEL 1), the group picked by `PORT_MUX_SEL`. Made in PORT1 R3c in snax-forge's image at snax-gvsoc `edaaa7dd` (`ry/port1`, `SnaxPortMux`, the streamer `snax_acc0/streamer_dot`), the task run at snax-forge `135cbdf` and the stall run at `16db29a` (the run code only between them; the generated files, `tasks.json` and the ELF the same):

    pixi run flow recipes/dot/dot_1_shared.json --platform platforms/snax_forge.json --trace task
    pixi run flow recipes/dot/dot_1_shared.json --platform platforms/snax_forge.json --trace stall

and copied from `out/flow/dot_1_shared_task/` as dot_1_enc's (`../dot_1_enc/README.md`): `run/events.log` (from `events.log.gz`), the three description files of `gen/` (`snax_forge.hjson`, `snax_forge_dot_1_shared_streamer_dot.hjson`, `accelerator.json`) and its `manifest.json`, `tasks.json`, `design/design_point.json` (its `graph_from` made relative), `check.json` (the profile's `total_cycles` and `functional_check`, each task's group with it) and `elf_symbols.json` (`run.json`'s, the ELF `sw/forge.elf` sha256 `5b26203e75d0a090`); from `out/flow/dot_1_shared_stall/` its `run/events.log` as `events_stall.log` (the same ELF, the same 287-cycle window). The run: 287 cycles, data 0 errors (1 word), COUNTERs `mult_vmul` 19 and `sum_vsum` 19 (16 beats each). Made again the same way when snax-gvsoc's grammar (`docs/EVENTS.md`) or the generated files change.

Not made again in CORE1 (one core, D170): these files record a run on the two-core cluster, still valid input for the converter, which reads any number of cores; the fixture changes only when the events or the generated files it reads change.
