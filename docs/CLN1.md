## How the tools ran

- **Tools, not in `pixi.toml`.** The pixi env has no pip, so the image's pip installed py3.11 wheels beside the repos: `pip3 install --no-deps --target $K/cln1-tools --python-version 3.11 --implementation cp --platform manylinux2014_x86_64 --only-binary=:all: vulture pytest-cov coverage` (vulture 2.16, pytest-cov 7.1.0, coverage 7.17.0), used as `PYTHONPATH=$K/cln1-tools pixi run python -m ...` (`$K` the folder holding the three checkouts). pixi's own pytest 9.1.1 stays the one loaded.
- **Unused code.** `pixi run python -m vulture snax_forge/ --min-confidence 60` (in the image): 16 hits; each name grepped (`grep -rnw NAME`) over the three repos' code, tests, `pixi.toml`, `gvsoc/Makefile`, `snax_forge.mk`, `.github/workflows` and docs. snax-gvsoc's `snax/` and `tests/snax/` by hand: every def, class and module constant (308, by `ast`) grepped the same way.
- **Coverage.** In the image: `pytest -q --cov=snax_forge --cov-context=test --cov-report=` (1242 passed, 2 skipped, 137 s; the gvsoc flow tests included), then `coverage json --show-contexts` (1.6 GB) and `coverage report -m`. The per-test line sets were read from the same data in `.coverage` (SQLite `line_bits` by context), parameters of one test merged: subsets and equal sets per test function (appendix A), functions with no caller in `snax_forge/`, `util/`, `kernels/`, the JS, `pixi.toml` or `gvsoc/Makefile` by AST name use, uncovered lines (appendix B). Copy-pasted tests: test bodies compared as ASTs with constants blanked (identical, or 75% of statements alike); helpers compared the same way across files.
- **Removed names and tags.** `grep -rnE` over the three repos (build, out, `.pixi`, `.git` folders left out) for the names of step 4, and for `\b(SG|GEN|LNK|FLOW|RET|CI|E2E|KER|IMP|CLN|VIS|VIEW|FE|REF)[0-9]+[a-z]?\b` and `[Rr]ound [0-9]+` in code.
- **Simplification, comments and docs.** `flow/run.py`, `design/check.py`, `run/beats.py`, `gen/gvsoc.py` and `brm/brm.py` read in full; the rest of `snax_forge/` and the docs of step 10 read by two delegated reads, each row with its grep. The rows' claims were checked again here where they lead to a change (the data.h seed, `bundle.missing`, the schedule and cluster task ends, `platform.py:478`).
- **Cluster tests (section 7).** In the image, from snax-forge's submodule: `make -C gvsoc sw`, `make -C gvsoc/snax-gvsoc/sw/apps/<p>` (into the submodule's ignored `build/`), then `out/snax-gvsoc/install/bin/gvrun --target T --work-dir ... --param chip/soc/binary=<elf> run` with T `snax_alu`, `snax_alu_sparse`, and `snax_hjson --param hjson=forge/vecadd/snax_forge.hjson`.
